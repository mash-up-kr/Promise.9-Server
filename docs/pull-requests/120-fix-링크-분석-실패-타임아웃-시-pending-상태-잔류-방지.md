 ## 📌 개요
오류 발생 시 `FAILED`를 기록하고, 작업 유실 등으로 오래 남은 `PENDING`도 주기적으로 정리합니다.

## ✅ 작업 내용 및 변경 사항
- [x] 요약에 필요한 크롤링 오류·타임아웃 발생 시 `FAILED` 기록
- [x] 재시도 성공 시 `SUCCESS`로 복구하는 기존 동작 유지
- [x] 상태 전이·타임아웃 정리 회귀 테스트 및 API·운영 문서 추가

## 💬 리뷰어에게
- 배포 후 첫 배치부터 기존의 오래된 `PENDING`도 정리됩니다.
- 타임아웃 배치는 상태만 변경하며 실행 중인 작업이나 재시도를 취소하지 않습니다.
- 성공한 링크와 삭제된 링크는 배치 대상에서 제외합니다.
- 태그, 임베딩만 실패한 경우 이미 성공한 요약 상태는 유지합니다.

## 🔍 상세 내용

Figma 링크 분석에서 원문 서버의 `403` 응답으로 재시도 상한에 도달했지만, 수집 실패 경로에서 DB 상태를 갱신하지 않아 계속 `PENDING`으로 노출됐습니다.

수집 실패 시 요약 상태를 `FAILED`로 기록하도록 보완했습니다.
프로세스 종료나 DB 장애로 상태 갱신이 누락된 경우에는 배치가 정리합니다.
대기 시간은 메모 수정에 영향받지 않도록 `createdAt`을 기준으로 판단합니다.
