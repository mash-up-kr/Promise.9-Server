## 💬 리뷰어에게
커밋은 이미지 인프라(`f40b4a6`)와 이메일 구현(`0070df5`)으로 분리했습니다. 배포 workflow는 main의 AWS 인증 설정을 유지하고 이미지 URL 변수만 추가합니다.

빌드·인프라 타입 검사와 Jest 테스트 301개가 통과했고, 커밋 분리 후 Bun 테스트 311개 및 lint-staged도 통과했습니다. 이미지 업로드 dry-run에서 PNG 38개(67,491바이트)를 확인했습니다. 브라우저에서 라이트·다크 및 모바일 미리보기를 확인했으며, 실제 SES 수신과 배포된 CloudFront 응답 검증은 아직 진행하지 않았습니다.

## 🔍 상세 내용
이미지 인프라는 `Promise9AssetsStack`으로 분리합니다. 업로드 CLI는 계정을 확인하고 파일명·내용 해시로 버전 경로를 만들며, 조건부 쓰기와 체크섬을 사용해 기존 객체를 덮어쓰지 않습니다. 이전 이메일의 이미지 URL이 유지되도록 기존 버전은 삭제하지 않습니다.

배포 순서는 에셋 스택 배포 → 이미지 업로드 및 공개 URL 확인 → GitHub repository variable `EMAIL_ASSET_BASE_URL` 등록 → 서버 배포 → 실제 메일 수신 확인입니다. AWS 리소스 배포는 아직 하지 않았습니다.

상세 버튼은 웹의 상세 경로로 이동하며 AI 요약 자동 스크롤은 포함하지 않습니다. 로컬 웹 저장소 확인 당시 상세 화면은 목업 데이터 기반으로, 실제 상세 조회·편집은 웹 연동이 필요합니다.
