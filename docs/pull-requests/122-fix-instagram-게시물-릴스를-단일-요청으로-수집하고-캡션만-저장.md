## 요약

- **릴스 썸네일 수집을 보완했습니다.** 기존에는 가져오지 못했던 릴스 표지를 가져옵니다.
- **일반 게시물·릴스를 `/embed/captioned/` 한 번으로 수집합니다.** 제목·캡션·썸네일을 같은 응답에서 얻습니다.
- **본문은 캡션만 사용합니다.** `metadata.description`에 최대 2,000자를 저장하고 AI에도 전달합니다. 중복되는 `content`는 `null`로 두며, 제목은 기존처럼 캡션 첫 줄 최대 100자입니다.

## 결론: 케이스별 수집 결과

실제 공개 게시물과 프로필로 확인한 결과입니다. 일반 피드 게시물은 이미지·캐러셀로 나눠 검증했습니다.

| 케이스 | 제목 | 내용 | 썸네일 |
| --- | --- | --- | --- |
| 일반 이미지 게시물 | ✅ 캡션 첫 줄 | ✅ 캡션 | ✅ 대표 이미지 |
| 캐러셀 피드 게시물 | ✅ 캡션 첫 줄 | ✅ 캡션 | ✅ 대표 이미지 1개 |
| 릴스 | ✅ 캡션 첫 줄 | ✅ 캡션 | ✅ 릴스 표지 |
| 계정 프로필 | ✅ 프로필 제목 | ✅ 원본 설명·본문 | ✅ 프로필 이미지 |

게시물·릴스는 **36/36회 제목·캡션 기반 수집과 썸네일 반환에 성공**했습니다. 릴스 썸네일 반환은 **기존 0/24회 → 변경 24/24회**입니다. 프로필은 기존 원본 URL 수집을 유지합니다.

내용은 저장용 수집(`collect`)에서 반환하며, 미리보기(`preview`)는 제목·썸네일을 반환합니다. 캐러셀은 대표 이미지 1개를 가져옵니다. 캡션이 없거나 추출할 수 없으면 제목·내용은 `null`입니다.

## 속도 개선

| 구분 | 기존 | 변경 | 소요 시간 감소 |
| --- | ---: | ---: | ---: |
| 미리보기 (`preview`) | 9.42초 | **1.22초** | **87.1%** |
| 저장용 수집 (`collect`) | 8.24초 | **1.10초** | **86.6%** |

공개 URL 6건을 변경 전후 각각 3회씩 측정한 **성공 요청의 중앙값**입니다. 기존 미리보기 타임아웃 1건은 제외했습니다. 동일한 TinyFish 캐시 설정(`ttl: 3600`)에서 측정했으며 DB 저장·AI 생성 시간은 포함하지 않습니다.

## 검증

- 게시물·릴스 비교 72회 + 프로필 4회, **총 76회 실제 호출**.
- 최종 `collect` 18/18회에서 캡션과 `content: null` 확인. 공통 요약·태그 프롬프트에서도 캡션 전달 확인.
- 최종 코드 관련 테스트 **173개**, 빌드·ESLint 통과.
