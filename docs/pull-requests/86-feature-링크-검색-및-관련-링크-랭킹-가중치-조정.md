## 변경 내용

한 사용자가 저장한 링크 안에서 검색 결과와 관련 링크의 순서를 개선하고, 폴더명으로 검색해도 해당 폴더의 링크가 노출되도록 검색 후보와 랭킹 신호를 확장했습니다.

API 엔드포인트와 응답 형식은 변경하지 않습니다.

| 기능 | 점수 구성 | 변경 전 | 변경 후 |
| --- | --- | --- | --- |
| Search | 제목 / 폴더 / 태그 / 본문 / 의미 유사도 | `0.35 / - / 0.20 / 0.15 / 0.30` | `0.10 / 0.15 / 0.10 / 0.05 / 0.60` |
| Related | 폴더 / 태그 / 제목 / 의미 유사도 | `0.20 / 0.30 / 0.15 / 0.35` | `0.10 / 0.25 / 0.10 / 0.55` |

### 폴더명 검색

- 제목·태그·본문·벡터 후보와 별도로 폴더명 부분일치 후보를 조회합니다.
- 활성 상태이면서 요청 사용자가 소유한 폴더만 검색합니다.
- 폴더명 후보에도 `folderId`, `unassigned`, `favorite`, `deleted` 검색 범위를 동일하게 적용합니다.
- 후보를 hydrate할 때 폴더명을 함께 조회해 `folderKeyword` 점수를 계산합니다.
- 다섯 후보 경로에서 각각 최대 30개를 조회하고, 합집합을 재랭킹해 상위 30개를 반환합니다.
- 폴더가 삭제됐거나 다른 사용자의 폴더인 경우 검색 신호에 포함하지 않습니다.

## 평가 데이터

### 기존 검색·관련 링크 평가

로컬 테스트 DB의 단일 사용자가 저장한 활성 링크 181개를 사용했습니다.

| 항목 | 규모 |
| --- | ---: |
| Search 평가 사례 | 121개 |
| Related 평가 사례 | 78개 |
| 전체 평가 사례 | 199개 |
| 평가 사례와 후보 링크 사이의 관련성 판정 | 1,279건 |

각 후보 링크의 관련성을 다음처럼 판정했습니다.

```text
3 = 매우 관련 있음
2 = 관련 있음
1 = 부분적으로 관련 있음
0 = 무관함
```

개발·음식·금융·원예·사진·음악·기후·언어 학습·육아·스포츠·건축·반려동물 등 여러 주제를 포함했습니다. 같은 주제의 링크뿐 아니라 같은 폴더·도메인에 있지만 내용은 다른 링크도 오답 후보로 넣었습니다.

### 폴더명 검색 추가 평가

현재 master 평가 계정의 활성 링크 308개를 기준으로 정확한 폴더명 검색 사례 8개를 추가했습니다.

- tuning: `맛집`, `코딩`, `청년혜택 정책`, `AI 채팅`
- holdout: `유틸리티`, `디자인 꿀팁`, `자기계발`, `예쁜 카페`
- `titleKeyword / folderKeyword / tagKeyword / contentKeyword / embedding` 5개 신호의 가중치 조합 3,701개를 비교했습니다.
- 기존형 tuning과 폴더형 tuning을 같은 비중으로 평가했고, 제목 가중치는 최소 `0.10`으로 제한했습니다.
- 폴더명 평가 사례는 사용자 폴더명을 외부 임베딩 API로 전송하지 않고 lexical 신호만 사용했습니다. 실제 검색 API의 임베딩 동작은 기존과 같습니다.

평가 데이터와 일회성 평가 도구는 저장소에 포함하지 않았습니다.

## 지표를 읽는 법

- `nDCG`: 관련성이 높은 링크가 상위에 배치됐는지 평가합니다. 순서가 좋을수록 1에 가깝습니다.
- `Recall`: 관련 링크 중 상위 결과에서 찾은 비율입니다. 누락이 적을수록 1에 가깝습니다.
- `MRR`: 첫 관련 링크가 나타난 순위를 평가합니다. 첫 관련 링크가 1위면 1, 2위면 0.5입니다.

아래 수치는 판정하지 않은 링크도 실제 상위 결과의 자리를 차지하는 것으로 계산한 보수적 지표입니다.

## Search 결과

### 기존 4개 신호 평가

가중치 선택에 사용하지 않은 기존 Search 평가 사례 47개에서 상위 10개 결과를 확인했습니다.

| 후보 | 제목 / 태그 / 본문 / 의미 유사도 | nDCG@10 | Recall@10 | MRR |
| --- | --- | ---: | ---: | ---: |
| main 기존값 | `0.35 / 0.20 / 0.15 / 0.30` | 0.882 | 0.855 | 0.940 |
| 기존 평가 선택값 | `0.10 / 0.25 / 0.20 / 0.45` | **0.904** | **0.867** | **0.975** |

### 폴더 신호 포함 재평가

기존형 holdout 47개와 가중치 선택에 사용하지 않은 폴더형 holdout 4개를 분리해 확인했습니다.

| 후보 | 제목 / 폴더 / 태그 / 본문 / 의미 유사도 | 기존형 nDCG@10 | 기존형 Recall@10 | 폴더형 nDCG@10 | 폴더형 Recall@10 |
| --- | --- | ---: | ---: | ---: | ---: |
| 폴더 추가 초기값 | `0.10 / 0.10 / 0.25 / 0.10 / 0.45` | 0.842 | **0.797** | 0.764 | 0.892 |
| 균형 선택값 | `0.10 / 0.15 / 0.10 / 0.05 / 0.60` | **0.843** | 0.783 | **0.856** | **1.000** |
| 변화 |  | **+0.001** | -0.014 | **+0.092** | **+0.108** |

태그 가중치만 `0.25 → 0.20`으로 낮춰 폴더 가중치를 `0.15`로 높이는 보수적 후보도 비교했지만 폴더형 holdout 순서를 개선하지 못했습니다. 기존형 Recall의 소폭 감소를 감수하더라도 폴더명 검색이 실제 순위에 영향을 주는 균형 선택값을 채택했습니다.

최소 점수 기준도 함께 검토했지만 적용하지 않았습니다. 최소 점수 `0.05`는 가중치 선택용 평가 결과를 개선하지 않았습니다.

## 운영 배포 환경변수

- 로컬 `.env`의 `OPENAI_API_KEY`를 값 노출 없이 GitHub Actions repository secret으로 등록했습니다.
- 배포 workflow가 `secrets.OPENAI_API_KEY`를 참조하고 생성하는 production env 파일에 기록합니다.
- DB, JWT, Google, Kakao, Apple, OpenAI 필수값이 없으면 이미지 배포 전에 실패합니다.
- production 앱 환경 검증에서도 `OPENAI_API_KEY`를 필수로 확인합니다.
- 선택값인 `KAKAO_CLIENT_SECRET`, `MASTER_ACCESS_TOKEN`, `MASTER_USER_ID`는 값이 있을 때만 env 파일에 기록합니다.
- 기본값이 있는 `DB_POOL_SIZE`, JWT 만료 시간, `LLM_DEFAULT_MODEL`, `LLM_REQUEST_TIMEOUT_MS`, `PORT`는 별도 설정 없이 기본값을 사용합니다.
- `GEMINI_API_KEY`는 현재 OpenAI 기본 구성에서는 필요하지 않으며 Gemini 모델 활성화 시 별도 전달이 필요합니다.
