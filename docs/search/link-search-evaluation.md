# 링크 검색 품질 평가 기록

2026-09-09 검색 정책 변경의 평가 구성, 선택 근거와 한계를 기록한다. 현재 운영 코드의 점수·임계값 규칙은 [검색 점수 산정](./link-search-scoring.md)을 참고한다.

최종안은 제목·AI 요약 키워드 비중 확대, 벡터 단독 후보의 평균+표준편차 임계값, 폴더명 전체 일치 우선순위다. 전체 테스트 실행과 관련성 판정은 `gpt-5.6-terra` 에이전트가 수행했으며 평가용 테스트·스크립트는 저장소에 포함하지 않는다.

## 1차안의 평가와 실패 근거

### 변경 사유

`스트레칭` 검색에 `색이 쉬워지는 색채학 기초개념 총정리`처럼 관련성을 찾기 어려운 결과가 노출된다는 사용자 피드백에서 시작했다. 기존 구조는 유사도가 낮아도 벡터 상위 후보를 회수하고 최소 관련성 조건 없이 최대 30개를 반환하므로, 가중치만 조정해서는 낮은 순위의 무관한 결과를 제거할 수 없었다.

기존 제목 키워드 가중치 0.10과 본문에 합쳐진 AI 요약 가중치 0.05를 각각 0.30과 0.25로 높였다. 벡터는 0.60에서 0.30, 태그는 0.10에서 0.05, 폴더는 0.15에서 0.05로 낮췄다. 이 값은 제목·요약 직접 일치를 우선한다는 제품 정책을 반영한 초안이며, 전체 사용자에 대해 탐색으로 구한 최적값이라고 해석하지 않는다.

제목·요약·태그·폴더 일치는 벡터와 관계없이 유지한다는 사용자 합의에 따라 보호한다. 키워드가 없는 후보에는 검색어별 분포를 반영하는 평균 초과 조건을 적용한다. 고정 최소 유사도는 추가하지 않았다. 이 절은 평균만 사용했던 1차안의 기록이며, 최종 구현은 위의 평균+표준편차와 정확 폴더 일치 우선순위를 따른다.

### 평가 구성 변경과 판단 기준

이전 태그·폴더 질의만으로는 본문에서 AI 요약을 분리한 효과와 제목 비중 확대를 확인하기 어렵다. 마스터 유저 링크 평가에서는 제목 키워드, AI 요약 키워드, 태그명, 폴더명 질의를 나누고, 특히 태그·폴더에 같은 검색어가 없는 제목/요약 사례를 별도로 집계한다. 동의어·자연어 질의는 키워드가 없는 관련 결과의 손실을, 무관 질의와 `스트레칭` 회귀 사례는 평균 필터의 한계를 확인하는 데 사용한다.

키워드 일치 여부를 관련성 정답으로 그대로 사용하지 않는다. 질의 의도와 제목·요약의 내용을 기준으로 관련성을 판단하고, 필터 전후의 키워드 후보 보존과 검색 결과의 의미적 관련성을 구분한다. 같은 데이터·검색 후보·질의 임베딩으로 이전 정책과 새 정책을 비교해야 가중치/필터 효과를 분리할 수 있다. 평가 결과는 상위 노출 순서뿐 아니라 반환 결과 수, 무관 결과 잔존, 관련 결과 누락을 함께 기록한다.

사용자 요청에 따라 테스트 실행과 실데이터 평가는 `gpt-5.6-terra` 에이전트에 위임한다. 평가 데이터·테스트·스크립트는 커밋에 포함하지 않고 실행 규모와 결과, 판단 근거를 이 문서에 남긴다.

### 실행 상태와 검증 한계

2026-09-09 기준 `gpt-5.6-terra`가 실행한 `bun run build`는 통과했고, `bun run lint`는 오류 없이 기존 검색 외 코드의 경고 2개만 보고했다. 가중치 합산에서 발생한 분모의 부동소수점 누적 오차는 백분율 단위로 분모를 합산하도록 수정했다.

저장소의 기존 검색 테스트 3개 suite / 27개 중 24개는 통과했다. 나머지 3개는 새 `summaryKeyword`가 반환되는 점을 반영하지 않은 기대값 2개와, 평균 이하 벡터 후보도 다음 페이지에 남는다고 가정한 이전 커서 기대값 1개다. 사용자 요청에 따라 저장소 테스트 파일은 변경하지 않았으므로 이 기대값 차이는 남아 있다. 새 정책용 임시 테스트는 `/tmp`에서 별도로 실행하며 커밋에 포함하지 않는다.

새 정책 검증 규모는 임시 테스트 2개 파일 / 10개 테스트 / 18개 expectation과 별도 정책 스크립트의 6개 assertion이며 모두 통과했다.

| 구성                                          |                      규모 | 확인 내용                                                                                                                                                   |
| --------------------------------------------- | ------------------------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 랭킹·정책 테스트                              | 9 tests / 12 expectations | 가중치, 제목 단독 일치, 요약 단독 일치, 태그·폴더 단독 일치, 기타 본문만 일치하는 후보의 필터, 평균 초과/이하, `null`·`NaN`, 임베딩 실패, 필터 적용 후 커서 |
| 실제 `SearchService.search` + repository mock |   1 test / 6 expectations | 평균 미만 1건 제외, 평균 초과 2건의 반올림 후 동점 정렬, 두 페이지의 누락·중복 없음, 필터 후 `totalCount=2`                                                 |
| 별도 정책 스크립트                            |              6 assertions | 합의된 유지/제외 조건에 대한 독립 입력 검증                                                                                                                 |

서비스 커서 테스트는 유사도 `0.1`, `0.500013`, `0.500014` 후보를 사용했다. 낮은 후보를 제외한 두 후보가 반올림 점수 `0.15`로 같아져도 id 내림차순으로 첫 페이지와 다음 페이지에 하나씩 반환되는지 확인했다. 이 합성 검증은 구현 계약을 확인하는 것이며 마스터 링크의 의미적 검색 품질을 대신하지 않는다.

AWS 재인증 후 `gpt-5.6-terra`가 운영 DB에 읽기 전용으로 접속해 마스터 유저 데이터를 확인했다. 이번 평가 대상은 활성 링크 1,553개이며, 임베딩 보유 1,545개, 제목 보유 1,514개, AI 요약 보유 1,545개, 태그 보유 1,545개, 활성 폴더 21개다. 개발 DB가 아니라 운영 DB의 실제 저장 데이터를 대상으로 한다. DB 데이터나 임베딩은 갱신하지 않는다.

실데이터 정책 비교는 61개 질의를 대상으로 수행했다. 먼저 저장소 후보 SQL과 동등하게 작성한 조회와 현재 신호/랭킹 함수로 오프라인 비교를 수행했다. 이어 읽기 전용 트랜잭션에서 실제 Drizzle DB 연결을 주입한 `SearchRepository → SearchService.search`를 61개 질의 모두에 실행해 다섯 후보 경로의 ID 합집합·hydrate 특성과 최종 결과 ID·점수·`totalCount`가 비교 로직과 61/61 일치함을 확인했다. HTTP 라우팅·인증 guard까지 포함한 API E2E는 아니다.

질의 임베딩은 동일 실행에서 변경 전후 비교와 실제 서비스 검증에 재사용했고, `round(5) → score/id 정렬 → 상위 30개` 규칙도 적용했다. 외부 임베딩 API에는 검색 질의만 전달하고 문서 원문은 새로 전송하지 않았다.

| --------------------------------------- | ------: | ------: | ------------------------------------- |
| 질의별 후보 합집합 누계                 |   2,341 |   2,341 | 같은 후보를 사용한 비교               |
| 질의별 최종 최대 30개 노출 누계         |   1,830 |   1,190 | 640건(35.0%) 감소                     |
| 제목·요약·태그·폴더 직접 일치 보호 후보 |       — |     944 | 순위 상한 전 보호 여부                |
| 위 보호 후보 중 요약 단독 일치          |       — |     401 | 제목·태그·폴더에는 일치하지 않은 후보 |

질의 구성은 제목 직접형 10개, AI 요약 문구형 10개, 주제·태그·폴더 성격의 키워드 질의 24개, 자연어 의도형 10개, 복합 무관 질의 7개다. 태그·폴더 질의가 하나의 키워드 범주에 묶여 있어 두 필드의 효과를 각각 추정하는 평가로 해석하지 않는다.

위 표는 실제 서비스 재검증과 동일한 캐시로 재현된 최종 실행을 기준으로 한다. 초기 실행의 1,188건은 당시 임베딩과 상세 결과가 저장되지 않아 차이 원인을 확정할 수 없으므로 최종 수치로 사용하지 않는다. 최종 실행에서는 상위 30개 제한 직전의 전체 필터 통과 수를 저장하지 않았으므로 초기 실행의 해당 수치도 혼용하지 않는다.

집계 단위는 질의-링크 쌍이므로 동일 링크가 서로 다른 질의에서 여러 번 포함될 수 있다. 필터 통과 후보와 실제 최종 노출 수를 구분하며, 반환량 감소만으로 관련성 품질이 개선됐다고 판단하지 않는다. 아래 이전 평가의 181개 링크/121개 검색 케이스 수치와 이번 데이터 규모를 혼용하지 않는다.

`스트레칭`은 후보 30개에서 7개가 통과했지만, 키워드가 전혀 일치하지 않는 선형대수 링크도 유사도 `0.30141`이 평균 `0.28017`보다 높아 남았다. 사용자가 지적한 색채학 링크는 이번 데이터의 변경 전 후보에도 없어 해당 사례를 재현해 제거했다고 결론낼 수 없다.

복합 질의에서도 한 토큰만 제목·요약·태그·폴더에 부분일치하면 보호된다. 이 정책은 합의된 키워드 후보 보존에는 부합하지만 질의 의도와 무관한 결과까지 보호할 수 있다. 따라서 평균 임계값만으로 관련 있는 결과만 노출한다는 목표는 충족하지 못한다.

### 실제 폴더명 검색 보강

최초 61개 질의를 저장된 후보의 태그·폴더명과 비교하니 태그명 전체 일치 질의는 8개였지만 폴더명 전체 일치 질의는 없었다. `주제·태그·폴더 성격`이라는 묶음만으로 실제 폴더 검색을 검증했다고 보기 어려워, 활성 링크가 있는 실제 폴더명 8개를 추가했다. 따라서 실제 서비스/DB 경로 검증은 총 69개 질의다. 이 8개는 위 61개 집계와 별도로 기록한다.

보강 평가에서도 읽기 전용 DB에서 실제 `SearchRepository`와 `SearchService.search`를 실행했고, 후보 ID·hydrate 특성·최종 결과 ID/점수/`totalCount`가 비교 로직과 8/8 일치했다. 후보 누계는 327건, 폴더 키워드 일치 보호 후보는 필터 전후 109/109건으로 100% 보존됐다. 최종 노출은 240→220건이었다. 상위 9개에서 선택한 폴더 소속 여부는 폴더명 검색 의도를 확인하기 위한 대리 지표이며, 의미적 관련성 판정과 구분한다.

선정 대상은 삭제되지 않고 활성 링크가 1개 이상 있는 검색 가능한 이름의 폴더다. 공백·대소문자 정규화 후 중복 이름과 이미 선택한 이름의 포함관계는 제외하고, 활성 링크 수 순으로 정렬한 0~100 분위의 8개 지점을 골랐다. 실제 선택 폴더의 링크 수는 1, 2, 3, 5, 7, 7, 10, 20개로 작고 큰 폴더를 함께 포함했다.

상위 9개 결과의 선택 폴더 소속 비율은 변경 전 33/72(45.8%)에서 변경 후 22/72(30.6%)로 낮아졌다. 따라서 폴더 일치 후보의 필터 보존만으로 폴더명 질의의 상위 결과 품질이 유지됐다고 볼 수 없다. 이 표본에서는 선택 폴더의 활성 링크가 8/8 모두 폴더 후보 경로에 포함됐으므로 해당 저하는 후보 누락으로 설명되지 않는다. 폴더 후보 경로가 30개 한도에 도달한 질의는 1개였으며, 일반적으로 더 큰 폴더나 부분일치 폴더가 많은 경우 전체 폴더 링크 회수·노출을 보장하지는 않는다.

### 대표 질의의 의미적 관련성 판정

61개 질의 중 제목·요약·주제 키워드·자연어·복합 무관 질의를 포함하도록 고른 대표 12개에 대해, 변경 전후 상위 9개 결과의 합집합을 별도 `gpt-5.6-terra` 에이전트가 판정했다. `strong`은 질의 핵심 대상과 목적을 직접 충족, `weak`은 주제의 일부 또는 인접 주제, `irrelevant`는 목적과 무관한 경우다. 복합 질의는 전체 의도를 충족해야 `strong`으로 인정했다. 사람의 독립 판정이나 61개 질의 전체의 의미 평가가 아니며, 맥락이 적은 질의의 판단에는 주관성이 있다.

| 상위 9개 이내 실제 노출의 판정 |    변경 전 |    변경 후 |
| ------------------------------ | ---------: | ---------: |
| 판정 대상 노출 누계            |        108 |        106 |
| 직접 관련 (`strong`)           | 28 (25.9%) | 29 (27.4%) |
| 주제 인접 (`weak`)             |         53 |         46 |
| 무관 (`irrelevant`)            |         27 |         31 |
| 직접 관련 + 주제 인접 비율     |      75.0% |      70.8% |

판정 규모는 고유 `(질의, 링크)` 122쌍이며 서로 다른 링크는 90개다. 표의 108/106은 질의별 노출 누계로, 같은 링크가 다른 질의에서 반복된 수를 포함한다. 변경 후 `스트레칭`이 7건만 반환되어 분모가 106이다. 직접 관련 비율은 약 1.4%p 높아졌지만, 무관 결과는 4건 늘었고 직접 관련+인접 주제 비율은 4.2%p 낮아졌다. 이 표본에서 새 정책이 일관되게 검색 품질을 높였다고 판단할 수 없다. 같은 12개 질의의 전체 반환 수는 360→260건으로 줄었지만, 상위 결과의 관련성 개선과는 별개의 지표다.

### 1차안에 대한 판단

실제 DB와 서비스 경로에서 합의된 필터/점수 계산이 동작한다는 구현 검증과, 무관한 검색 결과를 줄였다는 품질 검증을 구분한다. 새 정책은 첫 번째는 충족했지만, 두 번째를 일관되게 충족한다는 근거는 확보하지 못했다. 특히 키워드 한 토큰의 부분일치만으로 보호하는 규칙과 평균을 넘은 벡터의 실제 관련성은 별도 문제다. 폴더명 질의에서도 선택 폴더 소속 상위 결과 비율이 낮아졌다. 이 결과만으로 1차안을 확정하지 않고, 아래 후속 평가에서 키워드 보호를 유지하면서 벡터 기준과 폴더 우선순위를 개선했다.

## 후속 개선안의 선택과 독립 검증

### 고정한 정책과 선택 이유

가중치를 더 세분하거나 검색어별 예외를 추가하지 않고, 다음 두 변경으로 정책을 고정했다.

1. 키워드 일치 후보는 그대로 보호하고, 벡터 단독 후보의 기준을 `평균 + 1 × 모집단 표준편차` 초과로 강화한다. 현재 후보 분포에 따라 달라지는 기준이며 고정 유사도 하한은 아니다.
2. 폴더명 토큰열 전체 일치는 `0.9 + 0.1 × baseScore`, 그 외는 `min(0.9, 0.9 × baseScore)`로 배치한다. 폴더명 검색 의도를 약한 가산점만으로 처리할 때 나타난 순위 저하를 해결한다.

제목·요약 전체 일치와 태그 정확 일치에 추가 가산점을 주는 안도 비교했지만, 기존 판정에서 직접 관련 결과가 줄거나 이득이 뚜렷하지 않아 채택하지 않았다. 제목 0.30·요약 0.25·벡터 0.30·폴더/태그/기타 본문 각 0.05의 기본 가중치는 유지한다. 사용자와 합의한 네 필드의 키워드 일치 보호도 유지한다.

### 정책 선택 자료와 검증 자료의 분리

기존 의미 판정 12개 질의는 조정용 8개와 내부 검증용 4개로 고정해 비교했고, 폴더 8개도 4/4로 나눴다. 이 과정과 별도로 다른 `gpt-5.6-terra` 에이전트가 기존 12개와 겹치지 않는 6개 질의의 모든 후보 244쌍을 판정했다. 실험 담당자에게는 질의명만 알려 조정에서 제외하고, **정책을 고정한 뒤에만** 라벨을 공개했다. 공개 후 파라미터를 다시 맞추지 않았다.

독립 검증 질의는 제목형 `Swagger UI`, `Physical activity`, 요약형 `근육 회복 부상 예방`, `기후 변화 원인`, 자연어 `요세미티 방문 계획`, 복합 무관 질의 `고래 재즈 작곡`이다. 전체 후보 판정은 직접 관련 8·인접 주제 58·무관 178쌍이다. 저장된 제목·요약·태그·폴더를 바탕으로 판정했으며 원문 페이지까지 확인한 사람의 정답 라벨은 아니다.

### 의미적 관련성 비교

상위 9개 이내 실제 노출 누계를 비교한다. 최종안에서는 일부 질의가 9개보다 적게 반환된다.

| 평가군 / 정책                   | 직접 관련 | 인접 주제 | 무관 | 노출 합계 |
| ------------------------------- | --------: | --------: | ---: | --------: |
| 기존 12개 / 변경 전 HEAD        |        28 |        53 |   27 |       108 |
| 기존 12개 / 평균만 사용한 1차안 |        29 |        46 |   31 |       106 |
| 기존 12개 / 최종안              |        29 |        34 |   25 |        88 |

기존 12개에서 새로 노출된 미판정 후보 2건은 별도 에이전트가 추가 판정했다. `유연성 관절 가동 범위`의 돼지저금통 문서는 무관, `화성 정착 요리법`의 일반 행성 안내는 인접 주제로 분류했다. 기존 라벨은 바꾸지 않았다.

최종안은 기존 12개에서 1차안의 직접 관련 29건을 유지하며 무관 31→25건, 독립 6개에서도 직접 관련 8건을 유지하며 무관 20→13건으로 줄였다. 판정된 직접 관련 후보가 벡터 필터로 제외된 경우는 없었다. 이는 **회수된 후보와 판정 범위 안의 보존**이며 마스터 전체 링크에 대한 완전한 Recall을 보장하지 않는다.

인접 주제 결과도 함께 줄어드는 절충이 있다. 독립 6개에서 직접 관련 비율은 8/54(14.8%)→8/42(19.0%)로 높아졌지만 인접 주제는 26→21건으로 줄었다. 더 좁고 직접적인 결과를 우선하겠다는 선택이며, 무관 결과가 모두 없어졌다고 주장하지 않는다.

### 폴더명 검색과 노출량의 절충

폴더 8개에서 상위 9개 이내 해당 폴더 소속 결과는 변경 전 33/72, 1차안 22/72, 최종안 43/68이다. 최종안은 정확 폴더 일치를 먼저 배치하고 선택 폴더의 후보 55개를 모두 보존했다. 한 질의는 9개보다 적게 반환되어 최종 분모가 68이다.

기록된 후보 스냅샷에서 일반 61개 질의의 필터 통과 후보는 1차안 1,466→최종안 1,027, 그중 벡터 단독 후보는 522→83으로 줄었다. 9개 미만 결과를 반환한 질의는 3→24개다. 폴더 8개도 필터 통과 후보 286→183, 벡터 단독 120→17, 9개 미만 결과 질의 0→1개다. 이 값은 상위 30개 제한 **이전 후보 수**이며 최종 노출 누계와 구분한다.

### 최종 구현의 실제 검색 경로 확인

정책 고정 후 실제 `SearchRepository → SearchService.search`를 다시 실행해 일반 61개와 폴더 8개, 총 69개 질의가 비교 로직과 일치함을 확인했다. 읽기 전용 DB와 캐시한 임베딩을 사용했다. 최종 상위 30개 제한 후 실제 노출 누계는 일반 질의 897건, 폴더명 질의 176건이다. 폴더 키워드 보호 후보는 109/109건 유지됐다. 평가 스크립트와 임시 테스트는 저장소에 추가하지 않았다.

최종 코드에 대해 terra가 `bun run build` 성공, `bun run lint` 오류 0(기존 검색 외 경고 2개), 임시 경계/커서 검증 통과를 확인했다. 임시 검증은 평균+표준편차의 엄격한 경계, null/0/단독/동일 점수, 네 키워드 보호, 정확 폴더 우선, 0~1 점수, 반올림 후 두 페이지를 포함한다.

저장소 기존 검색 테스트는 최종적으로 27개 중 18개 통과·9개 실패다. 실패는 비폴더 점수 구간의 0.9 배율, 요약 신호 추가, 강화된 벡터 필터를 반영하지 않은 기존 점수/객체/커서 기대값이다. 사용자 요청에 따라 추적 테스트 파일을 변경하지 않았으므로, 기존 테스트 실행이 통과 상태라는 뜻은 아니다.

## 이전 가중치 조정 근거

아래 수치와 임계값 미적용 판단은 이번 변경 이전의 5개 신호 정책에 대한 기록이다. 현재 정책은 위 6개 신호와 동적 임계값을 따른다.

한 master 사용자의 활성 링크 181개를 대상으로 Search 121개와 Related 78개, 총 199개 평가 케이스에 1,279개 관련성 라벨을 구성했다. 개발·음식뿐 아니라 금융, 원예, 사진, 음악, 기후, 언어 학습, 육아, 스포츠, 건축, 반려동물 등 주제를 분산했고, Search에는 자연어 의도형 질의와 실제 제목에 가까운 질의를 함께 포함했다.

평가 케이스는 다음 기준으로 나눴다.

- `조정용 평가셋`: 여러 가중치 후보를 비교하고 최적 후보를 고르는 데 사용한다.
- `검증용 평가셋`: 가중치 선택에는 사용하지 않고, 선택한 가중치가 조정용 데이터에만 과도하게 맞춰지지 않았는지 확인한다.
- Related 재탐색은 기존형·제품형 사례가 한쪽으로 치우치지 않도록 두 집단을 같은 비중으로 평가하고, 개발 사례 57개를 5개 폴드로 교차 검증했다. 남은 review 21개는 최종 후보 확인에 사용했다.

관련성 판단의 주관성을 감안해 미판정 결과를 제외한 지표와 미판정을 무관으로 보는 보수적 지표를 함께 확인했으며, 최종 판단에는 다음 기준을 사용했다.

- `nDCG`: 관련성이 높은 링크가 상위에 배치되는지 확인한다.
- `Recall`: 관련 링크를 상위 결과 안에서 충분히 회수하는지 확인한다.
- `MRR`: 첫 번째 관련 링크가 얼마나 빨리 나타나는지 확인한다.
- 후보 커버리지와 실제 상위 결과를 함께 검토해 가중치만으로 해결할 수 없는 후보 생성 누락을 구분한다.

검증용 평가셋의 후보 커버리지는 Search 96.1%, Related 96.3%였다. 후보에 포함되지 않은 정답은 이후 정렬 가중치로 복구할 수 없으므로 이 수치는 랭킹 지표와 별도로 관리한다.

### Search

기존 평가 당시 가중치 순서는 `titleKeyword / tagKeyword / contentKeyword / embedding`이다. 폴더명 검색을 지원하면서 정확한 폴더명으로 검색한 8개 사례를 추가해 `titleKeyword / folderKeyword / tagKeyword / contentKeyword / embedding` 5개 신호의 3,701개 조합을 재탐색했다. 가중치 선택에는 기존형 tuning과 폴더형 tuning을 같은 비중으로 사용하고, 제목 가중치는 최소 0.10으로 제한했다. 폴더명 사례는 사용자 데이터가 외부 임베딩 API로 전송되지 않도록 lexical 신호만 사용했다.

| 후보             | 가중치                             | 기존형 holdout 보수적 nDCG | 기존형 Recall | 폴더형 holdout 보수적 nDCG | 폴더형 Recall |
| ---------------- | ---------------------------------- | -------------------------: | ------------: | -------------------------: | ------------: |
| 폴더 추가 초기값 | `0.10 / 0.10 / 0.25 / 0.10 / 0.45` |                      0.842 |         0.797 |                      0.764 |         0.892 |
| 균형 선택값      | `0.10 / 0.15 / 0.10 / 0.05 / 0.60` |                      0.843 |         0.783 |                      0.856 |         1.000 |

표는 미판정 결과도 실제 순위를 차지하는 것으로 계산한 보수적 지표다. 기존형 holdout은 폴더형 사례를 제외한 기존 검색 사례이고, 폴더형 holdout은 가중치 선택에 사용하지 않은 `유틸리티`, `디자인 꿀팁`, `자기계발`, `예쁜 카페` 폴더 사례다. 균형 선택값은 기존형 Recall이 0.014 낮아지는 대신 기존형 보수적 nDCG를 0.001 높이고, 폴더형 보수적 nDCG를 0.092, Recall을 0.108 높였다. 제목 검색의 기본 동작을 유지하기 위해 탐색 최적값이 더 낮더라도 제목 가중치는 0.10을 유지했다.

최소 점수 임계값 0.05는 조정용 지표를 개선하지 않았고 검증용 평가셋의 관련 결과 통과율만 96.1%에서 95.8%로 낮췄다. 0.075 이상에서는 Recall도 감소했으므로 임계값은 적용하지 않았다.

### Related

가중치 순서는 `folder / tag / title / embedding`이다. 단일 조정/검증 분할 결과에 의존하지 않도록 기존형 조정·제품형 조정·기존형 검증·제품형 검증의 네 하위집단을 구성했다. 829개 조합 중 가장 낮은 하위집단 nDCG를 우선 높이고, 이후 전체 평균 nDCG와 Recall을 비교하는 안정성 기준으로 다시 탐색했다.

| 후보               | 가중치                      | 개발 전체 보수적 nDCG | 개발 전체 Recall | review 보수적 nDCG | review Recall |
| ------------------ | --------------------------- | --------------------: | ---------------: | -----------------: | ------------: |
| 변경 전 main       | `0.20 / 0.30 / 0.15 / 0.35` |                 0.779 |            0.680 |              0.893 |         0.803 |
| 5-fold 최빈 후보   | `0.15 / 0.20 / 0.05 / 0.60` |                 0.801 |            0.692 |              0.906 |         0.832 |
| 안정성 기준 최종값 | `0.10 / 0.25 / 0.10 / 0.55` |                 0.796 |            0.697 |              0.904 |         0.822 |

5-fold 최빈 후보는 개발·review nDCG를 각각 0.005, 0.002 높였지만 개발 Recall을 0.005 낮췄다. 폴드별 선택값도 한 폴드에서는 tag 0.45까지 변했고, 각 폴드 밖 성능 평균은 보수적 nDCG 약 0.796, Recall 약 0.689로 최종값의 개발 전체 0.796, 0.697보다 낫지 않았다. 네 하위집단의 최저 성능을 우선한 재탐색에서는 `0.10 / 0.25 / 0.10 / 0.55`가 다시 선택됐으므로 이를 최종값으로 유지한다. 이는 기존 main 값으로 되돌린 결과가 아니라, 확장 평가셋의 하위집단 안정성을 기준으로 독립적으로 선택한 결과다.

이 결과는 한 사용자 데이터와 수동 관련성 판단에 기반한 오프라인 평가이므로 전체 사용자에 대한 보편적 최적값을 의미하지 않는다. 데이터 분포나 embedding 모델이 바뀌면 기존 검증용 평가셋만 반복해서 맞추지 말고 새 판정 데이터를 추가해 다시 검증해야 한다.

평가 데이터와 실행 도구는 일회성 실험 자료이며 사용자 요청에 따라 이번 변경의 커밋에도 포함하지 않는다. 반복 운영이 필요해지면 평가 케이스·판정 이력·가중치 버전을 관리하는 내부 평가 기능으로 구현한다.
