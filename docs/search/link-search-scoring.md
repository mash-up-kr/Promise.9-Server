# 링크 검색 점수 산정

`GET /links?q=...` 검색의 후보 수집, 점수, 정렬, 페이지네이션 규칙을 정리한다. 벡터 저장과 유사도 계산은 [벡터 검색 구조](./link-vector-search.md)를 참고한다.

## 구조

| 파일                                     | 역할                                            |
| ---------------------------------------- | ----------------------------------------------- |
| `link/search/search.service.ts`          | 신호별 후보 수집, hydrate, 최종 30개 상한, 커서 |
| `link/search/search.repository.ts`       | 제목·폴더·태그·본문·벡터 후보 쿼리              |
| `link/link-similarity.util.ts`           | 공용 토큰화·cosine 유사도 정규화                |
| `link/search/search-ranking.ts`          | 검색 신호 계산, 동적 임계값 필터와 관련도 정렬  |
| `link/search/search-ranking.constant.ts` | 검색 기본 가중치                                |

## 후보 수집

검색어를 소문자화하고 Unicode 문자·숫자 토큰으로 나눈다. NFKC 호환 정규화는 적용하지 않으며, 키워드 후보 조회와 키워드 점수에는 앞의 최대 12개 토큰을 동일하게 사용한다. 다음 다섯 경로에서 각각 최대 30개를 회수한다.

1. 제목 부분일치
2. 폴더명 부분일치
3. 태그 `normalizedName` 부분일치
4. AI 요약·메모·도메인·URL·metadata description 부분일치
5. 전체 검색어의 쿼리 임베딩 코사인 유사도

쿼리 임베딩과 네 keyword 후보 조회는 동시에 시작한다. 임베딩이 먼저 완료되면 keyword 조회 완료를 기다리지 않고 바로 벡터 후보 조회를 시작한다.

키워드 경로는 대상 필드를 소문자화하고 공백만 제거한 표현식에 `LIKE '%token%'`을 적용한다. 점수 계산도 같은 대상 표현식을 사용하므로 구두점 경계를 후보 단계와 다르게 제거하지 않는다. `pg_trgm` GIN 표현식 인덱스는 제목, 본문, 태그에 각각 존재한다. 폴더명은 사용자별 폴더 수가 링크 수보다 작다는 전제로 활성 폴더 범위를 조회하며 별도 trigram 인덱스는 두지 않는다. 1~2자 검색어는 추출할 trigram이 없어 사용자 범위 스캔으로 퇴화할 수 있다.

후보 합집은 최대 150개이며, 이 후보 풀에 관련성 필터를 적용하고 재랭킹한 상위 30개만 노출한다. 전체 사용자 범위의 exact top 30을 보장하는 구조는 아니다. API `limit`은 기본 9, 최대 30이며 이 30개 안에서 cursor 페이지네이션한다.

`folderId`, `unassigned`, `favorite`, `deleted`는 후보 범위에 적용한다. 검색 정렬은 관련도로 고정되므로 `sortBy`, `order`는 후보를 제한하지 않는다.

## 신호와 기본 가중치

각 신호를 0~1로 만든 뒤 가중 합산한다. 제목과 AI 요약의 직접적인 키워드 일치를 우선하고, 태그와 폴더는 보조 신호로 사용한다.

| 신호             | 원점수                                        | 기본 가중치 |
| ---------------- | --------------------------------------------- | ----------: |
| `titleKeyword`   | 검색 토큰 중 제목에 부분일치하는 비율         |        0.30 |
| `summaryKeyword` | 검색 토큰 중 AI 요약에 부분일치하는 비율      |        0.25 |
| `folderKeyword`  | 검색 토큰 중 폴더명에 부분일치하는 비율       |        0.05 |
| `tagKeyword`     | 검색 토큰 중 개별 태그 안에 부분일치하는 비율 |        0.05 |
| `contentKeyword` | 검색 토큰 중 기타 본문에 부분일치하는 비율    |        0.05 |
| `embedding`      | `clamp(1 - cosineDistance, 0, 1)`             |        0.30 |

```text
baseScore = titleKeyword * 0.30
      + summaryKeyword * 0.25
      + folderKeyword * 0.05
      + tagKeyword * 0.05
      + contentKeyword * 0.05
      + embedding * 0.30

score = exactFolderMatch
      ? 0.90 + 0.10 * baseScore
      : min(0.90, 0.90 * baseScore)
```

폴더명 전체 일치는 중복 제거·12개 제한 전의 원문 검색어와 폴더명 양쪽에 `tokenizeLinkText(value).join(' ')`를 적용한 토큰열 전체의 동등성으로 판단한다. 장식용 emoji·구두점 차이로 정확 일치가 사라지지 않게 한다. 전체 일치 폴더는 상위 점수 구간에 배치하며, 우선순위를 점수에 포함해 기존 `(score, id)` 커서와 0~1 응답 범위를 유지한다. 정확 폴더 일치도 최종 상위 30개 한도는 적용된다.

AI 요약은 별도 신호로 분리하고, 기타 본문은 메모·도메인·원본 URL·최종 URL·metadata description만 포함한다. 같은 요약 일치를 두 신호에 중복 반영하지 않는다. 후보 조회에서는 기존 본문 경로를 공유하므로 DB 스키마나 인덱스 변경은 없다.

벡터는 여전히 제목·태그·AI 요약을 합쳐 생성한 하나의 임베딩이다. 이번 변경은 제목/요약별 벡터 분리나 재생성을 수행하지 않는다.

키워드 점수는 후보 검색과 동일하게 대상 필드의 소문자화·공백 제거 후 부분일치를 사용한다. 따라서 `머신러닝`과 `머신 러닝`, `nest`와 `nestjs`는 일치하지만 `designsystem`과 `design-system`처럼 구두점을 사이에 둔 문자열은 일치하지 않는다. 태그도 각 `normalizedName` 안에서만 비교하므로 서로 다른 태그의 경계를 이어 붙여 일치시키지 않는다.

전각·반각 같은 호환 문자는 lexical 단계에서 합치지 않는다. 저장 문자열과 같은 문자 체계로 검색하면 일치하지만 `NestJS`와 `ＮｅｓｔＪＳ`의 교차 표기는 lexical 일치로 보장하지 않으며, 의미 검색은 embedding 신호가 보완한다.

링크 임베딩이 아직 없어 `embedding=null`이면 이를 비유사도 `0`으로 간주하지 않는다. 해당 후보에서 embedding 가중치 `0.30`만 제외하고 lexical 가중치 합 `0.70`으로 점수를 재정규화한다.

```text
scoreWithoutEmbedding = (titleKeyword * 0.30
                       + summaryKeyword * 0.25
                       + folderKeyword * 0.05
                       + tagKeyword * 0.05
                       + contentKeyword * 0.05) / 0.70
```

실제로 계산된 embedding 원점수 `0`은 결측값이 아니므로 기존 가중치에 따라 비유사 신호로 반영한다. 관련 링크도 embedding을 계산할 수 없으면 같은 원칙으로 context 가중치 합 `0.45`를 사용한다.

## 동적 관련성 임계값

필터는 순위 점수와 분리한다. 제목·AI 요약·태그·폴더 중 하나라도 검색 토큰이 부분일치하면 벡터 점수가 낮거나 없어도 후보를 유지한다. 이 조건은 필터에서 제외하지 않는다는 뜻이며, 최종 상위 30개 노출을 보장하지는 않는다.

네 필드에 일치가 없는 후보는 아래 조건을 만족해야 한다.

```text
meanSimilarity = 평균(후보 합집합의 계산 가능한 정규화 벡터 점수)
stddev = sqrt(평균((벡터 점수 - meanSimilarity)^2))
keep = embeddingSimilarity > meanSimilarity + stddev
```

- 평균에는 키워드 일치 후보의 벡터도 포함한다. 사용자·폴더·즐겨찾기·삭제 여부 등 요청 범위가 적용된 후보 합집합에서 계산하며, 사용자 전체 링크나 현재 페이지의 평균은 아니다.
- 벡터 점수는 먼저 0~1로 제한한다. `null`, `undefined`, `NaN`, 무한대는 평균에서 제외한다. 계산된 `0`은 포함한다.
- 키워드 미일치 후보의 벡터를 계산할 수 없거나 `평균 + 표준편차` 이하이면 제외한다. 기타 본문(메모·URL 등)에만 일치하는 후보도 이 규칙을 적용한다.
- 키워드 미일치 벡터 후보가 단독으로 평균을 구성하거나 모든 유효 벡터 점수가 같으면 평균을 초과하지 못하므로 제외한다. 동일 점수 합산의 부동소수점 오차를 줄이기 위해 첫 점수에 대한 편차로 평균을 계산한다.
- 임계값은 점수 반올림·정렬·상위 30개 제한·페이지네이션 전에 적용한다. `totalCount`에도 필터 통과 결과만 반영된다.

이 기준은 검색어별 점수 분포에 적응하지만 절대적인 관련성을 보장하지 않는다. 후보가 전부 무관해도 동적 임계값보다 높은 후보는 남을 수 있고, 토큰의 부분일치만으로 보호되는 결과도 있다. 또한 본문 후보 조회는 AI 요약과 기타 본문이 30개 한도를 공유하므로 후보에 들어오지 않은 요약 일치를 점수 조정으로 복구할 수 없다.

## 정렬과 커서

관련성 필터를 통과한 후보의 점수를 먼저 소수점 5자리로 반올림한 뒤 `(score DESC, id DESC)`로 다시 정렬하고 상위 30개를 선택한다. 응답 점수와 커서 비교 값이 같은 정밀도와 순서를 사용하므로, 반올림 후 동점이 된 후보도 id 순서대로 다음 페이지에 이어진다.

```text
nextCursor = base64url({ "v": "0.87342", "id": 42 })
```

`totalCount`는 커서와 무관한 상위 검색 결과 크기로 최대 30이다. 일반 목록 커서와 검색 커서는 서로 호환되지 않는다.

## 임베딩 실패 폴백

쿼리 임베딩 호출이 실패하면 경고 로그를 남기고 제목·폴더·태그·본문 신호로 검색을 계속한다. 이때 embedding은 결측 신호로 처리해 lexical 가중치 합 `0.70`으로 재정규화하며 커서 형식은 변하지 않는다. 제목·AI 요약·태그·폴더에 일치하는 후보는 유지하고 기타 본문에만 일치하는 후보는 제외한다.

검색 결과는 요청 시점마다 다시 계산하므로 페이지 사이에 embedding provider의 성공·실패 상태가 바뀌면 후보와 점수 순서도 달라질 수 있다. fallback 중 받은 cursor를 다른 ranking mode의 스냅샷으로 보장하지 않으며, 장애 전후에 페이지 결과가 불안정하면 첫 페이지부터 다시 조회해야 한다.

## 관련 링크와의 관계

검색과 관련 링크는 문자열·태그·cosine 유사도 계산만 `link-similarity.util.ts`에서 공유한다. 후보 쿼리는 `SearchRepository`와 `RelatedLinkRepository`, 점수 정책은 각각 `search/`, `related/` 내부에서 독립적으로 관리한다.

## 평가 근거

마스터 유저의 활성 링크 1,553개를 대상으로 실제 검색 69개 질의, 대표 12개 질의와 정책 선택에서 제외한 독립 6개 질의의 관련성을 평가했다. 테스트 규모·질의 구성의 변경 이유·채택하지 않은 안·최종 지표·검증 한계는 [검색 품질 평가 기록](./link-search-evaluation.md)에 정리했다.
